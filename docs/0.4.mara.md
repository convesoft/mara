# 0.4.0-alpha.1 — Execution, integration and reusable query engine

This is the confirmed target scope for 0.4.0-alpha.1, not a description of shipped
behavior. New contracts remain `draft`; verification items define release
checks, not passing execution evidence. Existing 0.3 usage contracts remain
current until implementation updates them. This bounded implementation does
not bump the application version or publish a release.

The original scope was renamed from 0.4.0 to 0.4.0-alpha.1. The user subsequently
added the reusable query/policy engine described below; this is additional
release work, not a claim that earlier execution evidence covers it. Release
preparation selects workspace version 0.4.0-alpha.1 before captured-candidate
verification.

## Outcome

One portable Rust document engine serves native embedded execution, a persistent
local daemon and browser-local WASM. Rust and TypeScript clients hide routing
and transport while exposing host capabilities and persistence differences.
The boundary is defined by [[DES-EXECUTION-BOUNDARIES]]. The same engine also
provides reusable factual queries, documentation-rule and contextual-gate
consumers, factual views and evaluation reports under [[DES-QUERY-POLICY-ENGINE]].

Detailed contracts live in [execution](execution.mara.md) and
[integration](integration.mara.md). The new query/policy/view contracts live in
[query engine](query-engine.mara.md). Its semantic handoff separates
[[DES-QUERY-INPUT-RESULT-CONTRACT]], [[DES-QUERY-COMPOSITION-CONTRACT]] and
[[DES-QUERY-CONSUMER-CONTRACT]], with discriminating fixture expectations in
[[VER-REUSABLE-QUERY-ENGINE]]. These specify behavior, not executed capability.
The bounded backend proof selects standard SELECT and a SHACL result bridge
under [[DES-QUERY-BACKEND-PROOF]], including proof format versions, actual
operations and explicit row-budget limits. It does not certify the complete
semantic catalog or integrated host workflows. The user clarified that the
[initial public v1 alignment](query-engine.mara.md#initial-public-v1-alignment)
retains the final JSON named-query definition shape and semantics while
renumbering format 5 to format 1; internal 3/4 checkpoints are normalized to it,
with no alternate versions. Independent format counters remain unchanged.
Standard SPARQL-only authoring under [[REQ-QUERY-SINGLE-LANGUAGE-AUTHORING]] and
[[ADR-QUERY-SPARQL-AUTHORING]], inference/editor integration and composition
redesign are deferred to later versions, not included in this release correction.
Existing semantic and host acceptance remain applicable;
[[DES-QUERY-NAMED-ADAPTER]] and [[ADR-QUERY-EXPLICIT-ANALYSIS-BOUNDARY]] still
retain runtime checks and explicitly projected support, not exhaustive static
analysis or complete hidden derivation provenance.

Focused consumer and transport tests are recorded in
[[DES-QUERY-CONSUMER-CONTRACT]] and [[VER-REUSABLE-QUERY-ENGINE]]. Their presence
is not integrated acceptance evidence: the final workflow must compare matching
artifacts across the selected hosts and retain tested revisions, environments,
commands and results. The complete semantic catalog and final supported-host
gates remain release requirements.

## Execution coverage

| Consumer | Execution path | Publication boundary |
| --- | --- | --- |
| Rust, CLI, MCP | Embedded native runtime | Existing guarded filesystem writes |
| Rust, CLI, MCP | Native client → daemon IPC | Same native runtime and filesystem writes |
| Node/TypeScript | N-API → native client | Embedded or daemon native writes |
| Browser client | Loopback HTTP → daemon | Native writes; explicit authorization |
| Browser client | Worker → bundled WASM engine | Memory workspace; export for caller publication |

The browser rows require a working library and test harness, not a graphical UI.
Project loading and persistence follow [[DES-JAVASCRIPT-CLIENT-ADAPTERS]],
[[DES-BROWSER-PROJECT-SNAPSHOT]] and [[DES-BROWSER-FILE-CHANGESET]].

## Excluded

- Engineering-template refinement and changes to the self-hosted schema or its
  policies; the query engine is demonstrated with fixture-owned definitions.
- External test/deployment execution or a provider plugin framework; hosts supply
  facts to the engine.
- Local or hosted graphical applications and their dedicated launchers, browser
  pairing, GitHub authentication, repository fetching, commit/PR publication and
  application-level workflow dispatch.
- Git revision comparison, item history, lifecycle-transition review and impact
  review. The former 0.4.0 knowledge-change review intention moves to Later in
  the [roadmap](../ROADMAP.md), without a new release commitment.
- Native draft/publish sessions, browser durable/offline synchronization and
  collaboration.
- Remote/cloud daemon hosting, OS service installation and automatic startup.
- Persisted indexes, WASM code-index import or browser-native indexing.
- New native platforms, public CJS library exports and cross-version daemon
  compatibility guarantees.
- Workspace aggregation, cross-project operations and additional browser-engine
  release certification.

## Release acceptance

Require the actual artifacts and workflows described by:

- [[VER-NATIVE-EXECUTION-BACKENDS]]: native routing, guarded edits, reconciliation,
  index reuse, lifecycle and measured cold/warm behavior.
- [[VER-INSTALLED-JAVASCRIPT-CLIENT]]: installed Node addon/types, native host
  packages and real Chromium-to-daemon operation.
- [[VER-BROWSER-DOCUMENT-ENGINE]]: the complete document profile in real browser
  WASM and validated exported source changes.
- [[VER-REUSABLE-QUERY-ENGINE]]: reusable facts, policy/gate separation and
  composition over fixture-owned vocabularies through actual native and browser
  consumers. Existing packaged-workflow evidence does not cover these additions;
  run the affected integrated gates again before final supported-host verification
  and guidance.

For 0.4.0-alpha.1, the user deferred dedicated manual Apple Silicon certification
on a user-provided host and the comprehensive contracts/public/agent-guidance
finalization pass. These are unscheduled later work, not prerequisites for this
alpha's scope integration or release preparation; neither is recorded as passed.
Existing contracts and basic accurate installation, version and limitation
guidance remain applicable.

The user explicitly retained existing automated CI and captured-release host
jobs, including macOS, and their required artifact/workflow checks. macOS support
and the platform matrix are unchanged. Linux results or cross-compilation do not
certify macOS; the captured release candidate still requires its automated
corresponding-host execution evidence and protected publication approval.

The user authorized preparing, pushing and merging this scope and publishing
0.4.0-alpha.1 to npm/GitHub without waiting for cloud PR review. This exception
waives the cloud-review wait for this alpha only; it does not claim a clean cloud
review or waive required fixes, CI, captured-candidate host checks or protected
release approval. Prerelease npm publication uses `next`, not `latest`.

Existing [release gates](release.mara.md) still apply. No mock backend, worker
stub, source-only rule validator or Node-only WASM test substitutes for these
workflows. Dependency portability must be checked before broad extraction under
[[ADR-PORTABLE-ENGINE-HOSTS]]; blockers require a scope decision, not silent
feature reduction. Work owns delivery decomposition and release preparation.
