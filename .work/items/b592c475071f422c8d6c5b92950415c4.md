## Outcome
Adapt the shared protocol to opt-in local browser HTTP with session authentication, explicit origin policy and exact project/destination authority before any project access.

## Acceptance
- [ ] HTTP is disabled by default and only binds loopback; use the same negotiated protocol/operation results as IPC with session token and explicit allowed origins, never wildcard origins.
- [ ] Authorize normalized/resolved exact roots and initialization destinations before file access or configured command execution; tokens/origins alone grant no project authority, and descendants/other projects/worktrees are not implicitly authorized.
- [ ] Permit authorized project operations including initialization, rollback and refresh; refuse daemon-wide lifecycle, policy and credential administration over HTTP without narrowing native IPC access.
- [ ] Wire actual endpoint/token reporting to the explicit local connection-info command; never put tokens in URLs, routine status or logs.
- [ ] Real HTTP tests verify disk mutations, disabled/unavailable/incompatible cases and token/origin/project/administration refusals before access. Keep final installed-client Chromium certification in the artifact-verification task.
