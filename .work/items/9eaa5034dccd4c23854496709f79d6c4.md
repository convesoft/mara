## Outcome
Define the shared Promise-returning TypeScript operation facade, errors and capabilities, and deliver its working Node ESM addon loader/adapter while leaving the CLI dispatcher separate.

## Acceptance
- [ ] Expose the full consistent document API, input/result/error types and bounded continuation with explicit project/workspace setup, operation/code capabilities and disk-versus-memory persistence.
- [ ] The Node ESM entry loads the real matching addon and delegates native routing without spawning the CLI; retain Node 24 minimum and no public CJS-library contract.
- [ ] Browser-safe shared/client modules do not eagerly import Node built-ins, N-API or filesystem loaders; backend-specific setup stays in adapters and no JS domain semantics are duplicated.
- [ ] Use the standard TypeScript compiler to check declarations against real Node client usage, including validation-invalid results versus typed errors and asynchronous lifecycle.
- [ ] Deliver a working Node path and reusable browser adapter boundary; closing the client does not stop the shared daemon. Record public entry/method/error/option contracts canonically.
