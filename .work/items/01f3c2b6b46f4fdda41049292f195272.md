## Defect and impact
CI/release source and host jobs set CARGO_TARGET_DIR=$SCRATCH/target while rust-cache uses the default checkout-relative target. Current rust-cache@v2 config.ts defaults workspaces to '.', splits an omitted target as 'target', and adds those workspace targets to cached paths; it does not select CARGO_TARGET_DIR. Workflow cleanup also removes scratch before the action's post-job save. Restored compiled dependencies are unused and new compiled dependencies are not preserved. Subsequent runs rebuild the native dependency tree. Registry/Git caches remain useful; package output and verification semantics are unaffected.

## Expected outcome
Configure the actual disposable Cargo target for standard compiled-dependency caching and arrange save/cleanup ordering so successful builds can populate the cache before disposable targets are deleted. Preserve session/job ownership, host isolation, source/artifact gates, captured release SHA and protected publication. Do not introduce a custom cache orchestrator.

## Deferral
Accepted non-blocking build-performance regression, unscheduled. The packaging item's explicit acceptance governs artifact completeness, version/platform boundaries, script-free installed resolution, prepublication assembly and protected gates; it does not require warm cloud-build caching. All functional local source/installed-artifact tests pass. No demonstrated timeout, incorrect output, data-loss risk or exploitable vulnerability makes this critical. Separate scheduling can restore caching without expanding the completed packaging contract. Raw contrary review verdict 'patch is incorrect' is preserved in the source review evidence.
