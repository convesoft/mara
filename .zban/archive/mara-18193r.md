## Decisions made

Part 1 (template, `mara prime`, CLI tests, AGENTS.md), written into DES-AGENT-GUIDE and VER-AGENT-GUIDE:

- A 0.3.0 project gets a note that says only how to convert it with `project convert`, on both surfaces, exit status 0; VER-AGENT-GUIDE has the case. DES-PROJECT-CONFIGURATION has every operation name the conversion in a 0.3.0 project, and an init note there would be wrong.
- `--project` naming a directory that is no project root gets the init note; any other selection error (a `.mara` symbolic link, an unreadable directory) fails as for every operation.
- "Compared in both directions" means: the guide names no undeclared operation or option, and names every operation that works in a project. `project init` and `project convert` appear only in the notes, `prime` in neither.
- `mara prime --format json` prints `{"format_version": 1, "text"}`, `text` holding the human form.
- Template syntax: `{{<words> <args>}}` and `{{--<option>}}` markers, and `cli: ` / `mcp: ` line prefixes. MCP renders an operation as `<group>_<verb>` without its arguments and an option as its name with `_` for `-`; to be checked against the server's real parameter names when wiring.
- The guide's notes have no heading, so only the full guide opens with `# Mara workflow`, which AGENTS.md uses to tell whether the guide is in context.

Part 2 (MCP server instructions, after mara-8vqk4a), written into DES-AGENT-GUIDE, DES-MCP-SERVER and VER-AGENT-GUIDE:

- MCP parameters carry the CLI's option names exactly (`clear-field`), so the MCP rendering writes an option as its name without `--`; the earlier `_` rule is gone.
- A server started without `--project` says that each tool takes `project` and to pass it for another checkout or worktree, and its init note names `project` as the directory to initialize. A server started with `--project` says its tools take no `project`. Otherwise both send the same instructions. The 0.3.0 note is the same for both.
- A server whose project selection fails other than by finding no project (a `.mara` symbolic link, an unreadable directory) sends no instructions; each tool call reports the error.
- `prime` is a CLI operation but no tool: a new `Run::Command` kind answers like a document operation without being served. `prime` and `mcp` are left out of the name comparison in both directions.

## Review

The one review (on `fafd20e`) found three defects in what the guide tells an agent, all fixed in the fix commit on top:

- The separator rule exempted the first item of a document, so an item after a title and introduction was silently read as narrative. The guide now requires `---` before every item, the first one after a title or other text included, and allows leaving it out only for an item that starts the document; DES-AGENT-GUIDE says the same. Test: `crates/mara/tests/prime.rs` writes the guide's hand-written example after a title and introduction, and the example starting a document, and requires both listed after one `project fix`.
- "On `changed-file`, read again and repeat" fails when the stop already replaced files (a rename's old ID is gone). The guide now tells the two cases apart: the message names replaced files, so run `project fix` and `project validate` and go on with the item's current ID or MID; otherwise read again and repeat. Test: `crates/mara/tests/authoring/pauses.rs` stops a rename across two documents after the first file and recovers as the guide says.
- The guide sent agents meeting `invalid-project` to `schema validate`, which reports only the schema file and the configuration's schema line. It now names `project validate`, and describes `schema validate` as checking the schema file; the `schema_validate` tool description says the same. Test: `crates/mara/tests/prime.rs` breaks `include`, sees `invalid-project`, runs the command the guide names after it and requires the error at the configuration's line.
- To keep the MCP instructions within 3,800 characters (3,785 unbound, 3,707 bound), four sentences outside the hand-authoring flow were shortened. mara-msymag now covers every heading with a `Type` table that is not the first block of its region.
