## Decisions made

- The addon: crate `mara-node`, napi-rs (`napi`, `napi-derive`), plain nx-rust `build` with `artifacts = []`, not `napi-build` (ADR-NAPI-RS-ADDON).
- The addon is `bin/mara.node` of the native package; its build is the `mara` beside it, which it finds itself (`dladdr`), not a path from JavaScript (DES-NODE-LIBRARY, DES-PACKAGES).
- An embedded host registers no signal handler: a signal that ends Node during an evaluation leaves the private directory, as SIGKILL does (DES-RULE-EXECUTION).
- The client API: `createClient({project, noDaemon})`, the project resolved when the client is created, a `project` argument refused; `run` as the workspace's; an addon that cannot load rejects with an `Error` holding the dispatcher's message (DES-NODE-LIBRARY).
- One `operations.d.ts`, the library's, copied into the browser package by `mara-browser:build` (DES-NODE-LIBRARY, ADR-NX-RUST-TASKS).
- The browser's daemon client checks argument names, presence and types as `mara mcp` does, with its messages, and reports the listener's `malformed-request` as `invalid-argument`, so its failures equal the other hosts' without a protocol change (DES-NODE-LIBRARY).
- In the parity cases, an argument that a client rejects before sending is compared with `mara mcp --no-daemon`, as the daemon case does; the daemon case's requests run on the 1× corpus with their items under `docs/agent/` and `src/agent/`; the package's `mara` is made non-executable around each daemon call, so that its CLI can read `served` between calls.
- VER-BROWSER-ACCESS: a refusal has the status and body that DES-BROWSER-PROTOCOL gives its check; the disallowed preflight is refused as the origin check refuses.
- DES-BROWSER-PROTOCOL: during a stop, preflights, the refusals of steps 1 to 6 and unavailable operations are still answered; step 7 is refused with 503 `stopping`, as it runs after admission.

- Fix round 1, decided by the orchestrator: an embedded host never sets the umask; where `/proc/self/status` does not report it, a call to the daemon runs in-process (DES-NODE-LIBRARY, DES-DAEMON-LIFECYCLE).
- Fix round 1: the addon's build is frozen when first needed, and the addon starts no daemon of a file that replaced its `mara` (DES-NODE-LIBRARY, DES-DAEMON-LIFECYCLE).
- Fix round 1: a required MCP parameter is missing when left out, `null` or an empty array, and `mara mcp`, the addon and the workspace refuse it before the operation runs, naming the parameter (DES-MCP-SERVER); the CLI keeps its operation's message, so VER-CLI-MCP-PARITY's MCP cases of a missing required option compare the refusal, not the text.
- Fix round 1: the browser's daemon client maps only a value's `malformed-request` (`` `<option>`: <reason> ``) to `invalid-argument`; where several parameters are wrong it may name a later one than `mara mcp` (DES-NODE-LIBRARY).
- Fix round 1: `mara:test` forwards its options to `mara-node:build` (ADR-NX-RUST-TASKS).
