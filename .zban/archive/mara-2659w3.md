Goal: the file-read counter of DES-PERFORMANCE-HARNESS (docs/performance.mara.md) counts every read that project loading makes, so VER-NESTED-PROJECTS (docs/verification-documents.mara.md) can show that an operation reads no file of another project.

Context: `mara::project::load` in crates/mara/src/project.rs reads `.mara/config.toml` and the schema file with `fs::read`. `mara::project::select` and `recognize` only stat `.mara/config.toml` and `.mara/project.toml` of the start directory and its ancestors; they read no file. Both landed with mara-b52dg3, in parallel with the harness (mara-csmk0c), so neither is instrumented. Loading is linear in the size of the two files, so no scaling case is needed.

- [x] Each read in `mara::project::load` counts as a file read
- [x] A counter test shows that selecting and loading a project nested in another reads exactly that project's configuration and schema

## Summary of Changes

- `mara::project::load(root, work: &mut WorkCounts)` (crates/mara/src/project.rs): the request's counts are its second argument, passed on to `read`, which adds 1 to `file_reads` after each successful `fs::read`. A path refused for `symbolic-link` or `outside-project` is never opened, so it adds nothing. `select` and `recognize` only stat, so their signatures are unchanged.
- crates/mara/tests/project.rs: `a_nested_project_reads_only_its_own_configuration_and_schema` is the counter test. It selects from inside the inner and the outer project, and with `--project` naming each project from inside the other. Each project's configuration names its own schema file, so the loaded configuration and schema show which files were read. The other counters stay 0 and `file_reads` is exactly 2. Every refusal case now asserts that the refused file is not read: 0 reads when the refusal is at line 1, 1 read (the configuration) when it is at the schema line. A missing schema gives 1 read and an unreadable configuration 0.
- The real-CLI form of the case is already named, in the VER-NESTED-PROJECTS items of mara-000f9q and mara-bmc9gc. That Verification defines "uses only a project" by the file-read counter, and DES-INPUTS-AND-KEYS makes the configuration and schema inputs. So neither issue was edited.
- crates/mara/tests/performance/corpus.rs: updated for the new signature.

Checks: all six local checks of AGENTS.md pass (fmt, clippy with warnings denied, workspace tests, release performance test, wasm32 engine build, `zban check`). As a mutation check, dropping the count fails 6 tests, and counting failed reads fails 2.

## Decisions made

- DES-PERFORMANCE-HARNESS (docs/performance.mara.md): a file read is one read of a file's contents by the host. A stat or a failed read is none. So project selection, the symbolic-link and nested-root checks, and a refused path count no file read, and reading the same file twice counts 2.
